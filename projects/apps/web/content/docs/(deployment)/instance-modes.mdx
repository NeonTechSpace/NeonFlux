---
title: Instance modes
description: How NeonFlux separates single and multi instance behavior.
---

NeonFlux has one deployment mode at a time. The bot writes deployment behavior into Convex during startup, and web reads that Convex value as the source of truth.

<Tabs items={['Single instance', 'Multi instance']}>
  <Tab>
    Single instance targets one configured community.

    The dashboard does not show a community picker. If a user logs in without Manage Server permission for the configured community, the site shows a not-authorized screen for that community.

  </Tab>
  <Tab>
    Multi instance uses one bot token for many installed communities.

    The dashboard lists only communities where the user has Manage Server permission and the bot is installed.

  </Tab>
</Tabs>

## Source of truth

Deployment behavior starts in bot environment variables, then becomes Convex-backed config.

| Area               | Source                     |
| ------------------ | -------------------------- |
| Bot token          | Bot environment            |
| Instance mode      | Bot bootstrap, then Convex |
| Single guild id    | Bot bootstrap, then Convex |
| Public web origin  | Bot bootstrap, then Convex |
| OAuth and sessions | Web environment            |

This avoids asking both services to carry the same behavior flags.

## Dashboard behavior

Single instance goes straight to the configured community. Multi instance shows a community picker with only manageable installed communities.

<Callout title='Optional invite action' type='info'>
    Multi-instance navigation shows the bot invite action only when `FLUXER_BOT_INVITE_URL` is configured. The dashboard
    still lists only communities that are both manageable by the signed-in user and installed for this deployment.
</Callout>
